# 공통 기준선

모든 기능에 적용한다. 기능마다 새로 도출하는 품질 시나리오(Q)는 이 밖의 것만이다. 기능에 해당하는 번호만 골라 적는다.

- B1 호환성: 일반 브라우저와 Flutter WebView 양쪽에서 동작한다. 로그인, 이미지 선택, 공유, 뒤로 가기는 환경별 차이를 확인한다 — 브라우저 자동·수동, WebView 수동
- B2 상호작용 역량: 데이터를 보여 주는 화면마다 로딩·빈·오류 상태가 있다 — 에이전트 리뷰
- B3 상호작용 역량: 390px 모바일에서 가로 스크롤 없이 보인다 — 수동
- B4 상호작용 역량: 공통 상단 바·하단 내비 없이 화면 전체를 그리는 페이지는 `components/ui/Layout/SafeAreaScreen`으로 시작하고, 하단 고정 버튼은 safe area 위 12px에 둔다 — 에이전트 리뷰, 수동
- B5 보안성: 로그인이 필요한 페이지나 행동은 비로그인 사용자를 로그인 페이지로 보내고, 로그인 후 `returnTo`로 그 페이지나 행동을 시작한 주소에 복귀시킨다. 페이지 진입은 `useRequireLogin`을 쓴다 — 자동(RTL), 수동
- B6 유지보수성: 서버 상태는 TanStack Query로만 관리하고 Zustand에 복제하지 않는다. 계산 가능한 값을 별도 상태로 저장하지 않는다 — 에이전트 리뷰
- B7 유지보수성: 같은 역할의 공통 컴포넌트·훅을 중복 구현하지 않는다 — 에이전트 리뷰
- B8 유지보수성: lint와 타입 검사를 통과한다 — 자동
- B9 검색 노출: sitemap에 들어가는 공개 페이지는 JS 실행 없이 받은 첫 HTML에 핵심 정보(제목, 본문 요약)와 `<title>`·description 메타, 해당하는 구조화 데이터(JSON-LD)가 있다 — 자동(프로덕션 빌드 HTML 요청 후 확인)
