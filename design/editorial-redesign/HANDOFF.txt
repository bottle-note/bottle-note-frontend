Bottle Note — 페이지별 상세 디자인 인수인계
기준일: 2026-10-03
관련 이슈: https://github.com/bottle-note/workspace/issues/451

1. 이번 드래프트의 목적

현재 editorial-redesign HTML 시안을 다음 세션의 디자인 기준으로 보존한다.
이 시안에서 출발해 페이지별 상세 디자인을 한 화면씩 다듬고 사용자와 확인한다.
전체 톤을 다시 탐색하거나 운영 앱 전체를 한꺼번에 구현하는 단계가 아니다.
이 PR 자체가 #451의 운영 앱 반응형 대응 완료를 의미하지 않는다.

2. 가장 먼저 볼 자료

- index.html: 승인된 홈 방향. 홈 배너가 중요하다.
- explore.html / profile.html: 목록과 기록 화면의 기준 톤.
- imports.html / import-detail.html / importer.html: 다른 화면과 톤을 맞춘 최신 수입통관.
- README.txt: 실행법, 18개 HTML, 실제 동작과 예시 데이터 범위.
- design-qa.md: 이전 브라우저 검증 이력. 맨 위 '톤 통일'이 최신 수입통관 결과.
- screenshots/: 최신 모바일·중간 폭·웹 및 라이트·다크 화면.
- references/: 선택한 초기 컨셉, 이전 상태 및 비교 자료. 현재 기준은 최신 실행 HTML이다.

저장소 루트에서 실행:
python3 -m http.server 8787 --bind 127.0.0.1 --directory design/editorial-redesign
http://127.0.0.1:8787/

HTML/CSS/JS/자산이 포함되어 열 때 빌드·환경변수·로그인이 필요 없다.
이전 Cloudflare Quick Tunnel 주소는 임시 주소다. 영구 프리뷰로 의존하지 않는다.
필요할 때 위 서버를 실행한 상태에서 cloudflared tunnel --url http://127.0.0.1:8787 로 새 주소를 만든다.

3. 유지할 디자인 방향

- 책갈피·노트 개념, SUIT, 코랄 행동색, 오크 계열 다크모드.
- 기존 BookmarkTab, Button, SearchBar, Star/StarRating 등 실제 컴포넌트의 형태.
- 병 이미지는 배경이 있는 원본이다. 흰 배경과 병·라벨 전체 비율을 유지한다.
- 기존 제품명·영문명·사진·평가·기록이 중심인 담백한 앱/웹 화면.
- 넓은 빈 카드, 과장된 제목, 장식용 지표를 추가해 공간을 채우지 않는다.
- 홈 배너를 유지한다. 사용자가 홈 방향을 긍정적으로 평가했다.
- 둘러보기·리뷰·시음회·마이보틀은 이미 여백을 줄였고 수입통관도 같은 톤으로 맞췄다.
- 모바일은 하단 메뉴·목록 1열, 현재 시안에서는 700px부터 옆 메뉴·목록 2열.
- 700px은 프로토타입 기준이다. 실제 기기 출시 규격이나 확정된 운영 breakpoint가 아니다.
- 기본적으로 기존 기능·데이터를 재배치한다. 큰 구현 변경이나 새 서버 데이터가 필요하면 화면별로 쟁점을 드러낸다.

4. 다음 세션 진행 방법

1) 사용자와 이번에 다듬을 페이지 하나를 정한다. 별도 지정이 없으면 위스키 상세를 먼저 제안한다.
2) 해당 HTML을 모바일·웹에서 열고 실제 운영 route·인접 컴포넌트·DESIGN.md·토큰을 함께 확인한다.
3) 사용자의 행동, 정보 우선순위, 1열/2열 전환, 고정 행동 영역을 정리한다.
4) 현재 HTML에 해당 페이지의 상세 디자인을 반영한다. 다른 화면으로 연결되는 링크는 유지한다.
5) 필요한 상태(긴 이름, 데이터 적음/없음, 선택, 필터, 로그인 필요 등)를 구분한다.
6) 모바일 390px, 좁은 320px, 중간 834px, 웹 1440px와 두 테마에서 확인한다.
7) Playwright MCP로 주요 입력·클릭·뒤로 가기·스크롤을 확인하고 스크린샷과 QA 기록을 갱신한다.
8) 사용자 확인을 받은 화면을 이 문서 아래 진행표에 기록한 뒤 다음 페이지로 간다.

상세 디자인 확인과 운영 코드 반영은 별도 단계다. 운영 반영 요청 전까지 디자인 HTML을 수정한다.
예시 데이터의 필드나 상태를 실제 API 계약으로 간주하지 않는다. 운영 연동 시 OpenAPI와 실제 domain을 확인한다.

5. 페이지별 상세 디자인 진행표

현재 상태는 모두 '기준 시안 있음 / 페이지별 상세 확정 전'이다.
아래 순서는 제안이며 사용자가 정한 순서를 우선한다.

순서 | 화면 | HTML | 상세 검토할 내용
1 | 위스키 상세 | whiskey.html | 이미지·별점·찜/기록/공유, 정보·리뷰 배치, 적은 데이터
2 | 둘러보기·검색 | explore.html, search-input.html | 분류·정렬·검색·긴 제품명·빈 결과
3 | 리뷰 목록·상세 | explore.html?tab=리뷰, whiskey-reviews.html, review.html | 제품 식별·본문·사진·태그·댓글·공개 범위
4 | 리뷰 작성·수정 | write-review.html | 별점·가격 단위·장소·이미지·태그·키보드·저장 행동
5 | 시음회·프로그램·큐레이션 | curation.html, article.html | 일정·장소·가격·본문·신청 행동과 데이터 유무
6 | 마이보틀·프로필 | profile.html, my-bottle.html, edit-profile.html | 전체·별점·리뷰·찜, 타인 프로필, 기록 적음/없음
7 | 수입통관 | imports.html, import-detail.html, importer.html | 품목/수입사 목록·검색/필터·연결 제품·상세 정보
8 | 히스토리 | history.html | 날짜별 기록과 상세 이동
9 | 설정·로그인 안내 | settings.html, login.html | 설정 항목·테마·로그인 복귀와 실제 인증 연결
10 | 홈 최종 정합성 | index.html | 승인된 배너·섹션, 상세 화면들과 링크·스타일 일치

완료한 페이지와 사용자 피드백은 여기에 추가한다:
- 아직 페이지별 상세 디자인 확정 기록 없음.

6. 편집 위치와 정적 HTML 주의사항

- src/pages.js: 공통 셸·기존 페이지·상태·페이지 이동.
- src/collections.js + collections.css: 둘러보기·리뷰·시음회·마이보틀.
- src/imports.js + imports.css: 최신 수입통관 목록·상세.
- responsive.css + layout.css: 공통 반응형·레이아웃.
- src/real-ui.jsx / src/next-compat.jsx: 실제 React 컴포넌트와 정적 시안 연결.
- data.js: 예시 콘텐츠. 실제 데이터로 확정된 값이 아니다.
- component-manifest.json: 가져온 기존 컴포넌트 목록.

실행 시 JS가 화면을 다시 렌더링한다. HTML에는 공유 편의를 위한 렌더링된 마크업도 들어 있다.
HTML만 고치면 실행 시 덮어써진다. src/CSS를 먼저 수정하고 브라우저 확인 후 HTML 마크업도 갱신한다.
export-html.mjs는 빈 셸을 출력하므로 이를 실행한 것만으로 정적 마크업 갱신이 끝난 것으로 보지 않는다.
build.mjs는 기존 컴포넌트 번들을 다시 만들 때만 필요하며 현재 esbuild의 pnpm 내부 경로를 사용한다.
다른 설치 환경에서는 경로를 확인해야 한다. 공유된 real-ui.js와 product-ui.css를 쓰는 데 재빌드는 필요 없다.

7. 검증 범위와 남은 일

2026-10-01 브라우저 기록:
- 최초 18화면 × 3개 폭 × 2개 테마: qa-results.json.
- 목록 개선 5뷰 × 4개 폭 × 2개 테마: collections-qa-results.json.
- 최신 수입통관 4뷰 × 4개 폭 × 2개 테마: imports-tone-qa-results.json.
- 위 검증에서 가로 넘침·깨진 이미지·실행 오류가 없었고 주요 이동/입력을 확인했다.

미검증/후속:
- 실제 폴더블 기기·회전·Flutter WebView·키보드·Safe Area의 운영 동작.
- 실제 API, 인증, 신청/결제, 알림 저장, 파일 업로드와 외부 서비스 전체 동작.
- 현재 예시의 날짜·수입사·제품 연결은 목업이며 실제 수입 사실을 의미하지 않는다.
- 사용자별 기록은 브라우저 sessionStorage 예시다. 실제 계정에 저장되지 않는다.
- 프로덕션 자동 테스트/빌드 결과와 이 HTML 검증을 혼동하지 않는다.

8. 이 드래프트에 포함하지 않은 로컬 작업

기존 작업 트리에 /search 레거시 제거 관련 운영 코드 변경이 남아 있다.
next.config.mjs, src/app/(primary)/search, sitemap, routes, SEO 유틸 변경은 이 디자인 PR에 포함하지 않았다.
새 체크아웃에서는 그 변경이 따라오지 않는다. 레거시 /search를 신규 화면으로 복원하지 않는다.
/search/input 및 /search/all/:id는 별개 흐름이며 page-list.json은 당시 경로 참고표다.
과거 design 하위의 다른 컨셉·ZIP과 .playwright-mcp 로컬 로그도 이번 기준본에 포함하지 않았다.

책갈피·노트, SUIT·코랄·오크, 홈 배너와 기존 목록 톤을 유지하고 실제 컴포넌트를 참고해줘.
