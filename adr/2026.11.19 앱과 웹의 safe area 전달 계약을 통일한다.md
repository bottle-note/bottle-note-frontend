# 앱과 웹의 safe area 전달 계약을 통일한다

- 결정일: 2026-11-19
- 대상: 앱 WebView와 웹 루트 레이아웃·safe area 변수
- 관련 작업: Linear HYE-95

## Context(배경)

Android WebView는 버전에 따라 `env(safe-area-inset-*)`를 0 또는 실제 높이로 반환한다. 앱과 웹이 모두 여백을 두면 이중 여백이 생긴다.

- Q1: 앱이 시스템 바 높이를 주입한 상태에서 페이지를 열면, 첫 페인트 전에 내용 여백이 반영되어야 한다. 합격 기준은 head 인라인 스크립트의 동기 실행이다.
- Q2: 앱 높이가 숫자가 아니거나 음수·비유한 값이면, 해당 CSS 변수를 설정하지 않고 기존 값은 변경 이벤트에서 제거해야 한다.
- B1: 일반 브라우저와 Flutter WebView에서 각각 동작해야 한다.

## Decision(결정)

앱 1.0.10부터 iOS·Android 모두 WebView를 화면 끝까지 그리고, 네이티브 여백이나 CSS를 추가하지 않는다. 웹이 배경을 시스템 바 뒤까지 그리고 내용 여백을 맡는다.

앱은 `AT_DOCUMENT_START`에 `window.BottleNoteApp = { safeArea: { top, bottom } }`을 주입한다. 높이는 0 이상의 유한한 숫자이며 단위는 CSS px다. 회전·폴더블 상태·내비게이션 방식이 바뀌면 값을 갱신한 뒤 `window`에 `bottlenote:safearea` 이벤트를 보낸다.

웹은 `max(env(), 앱 값)`을 사용한다. 앱 값이 없는 브라우저와 구버전 iOS는 `env()`를 유지한다. `#bottle-note-native-safe-area`가 있는 구버전 Android는 앱이 이미 시스템 바 자리를 비우므로 웹 safe area를 0으로 둔다.

## Status(상태)

Accepted(승인됨). 구버전 Android 실기기 검증(F4)은 사용자 요청으로 후속 확인한다.

## Consequences(결과와 영향)

앱의 높이 주입 시점과 CSS px 변환이 계약을 지켜야 첫 화면 여백을 보장한다. 웹의 값 변환·초기 적용·이벤트·잘못된 값 제거는 `src/lib/safe-area.test.ts`로 검증하고 실제 시스템 바·키보드와의 배치는 앱에서 별도로 확인한다.
