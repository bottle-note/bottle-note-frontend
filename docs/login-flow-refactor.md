# 로그인 흐름 리팩토링 TODO

## 합의한 동작

- 모달과 CTA는 같은 로그인 진입 함수와 `returnTo` 전달 방식을 사용한다.
- 로그인 진입은 `replace`, 성공 후 복귀도 `replace`를 사용한다.
- 로그인 화면의 상단 뒤로가기도 같은 `returnTo`로 `replace`한다. 브라우저 자체 뒤로가기는 실제 기록을 따른다.
- 앱에서 `A → B → 로그인 → B 복귀` 후 뒤로가기는 A로 이동한다. 로그인 전 B 기록을 추가로 남기지 않는다.
- 웹의 외부 인증 기록은 남아도 된다. 인증된 사용자가 과거 `/login` 기록을 만나면 로그인 화면을 표시하지 않고 이동 방향대로 건너뛴다.
- 인증된 사용자의 `/login` 직접 진입은 유효한 `returnTo`로 이동하고, 없으면 홈으로 이동한다.

## 진행 방식

- 각 단계에서 구현 → 관련 자동 검증 → 가능한 실제 흐름 확인 → 변경 코드 설명 및 사용자 검토를 진행한다.
- 다음 단계의 구현은 앞 단계의 코드 검토를 마친 뒤 진행한다.
- 실제 인증을 우회하거나 목킹하지 않는다. 앱 WebView 검증과 일반 브라우저 검증 결과를 구분한다.
- 제품 코드 변경과 검증 결과는 각 단계 완료 시 기록한다.

## 결정한 취소 동작과 후속 작업

- 성공과 상단 뒤로가기는 동일한 `returnTo`를 사용한다. 문의 작성 목적지라면 취소도 문의 작성으로 이동한다.
- MBTI도 상단 뒤로가기는 전달한 `returnTo`를 그대로 사용한다. 로그인 실패 시 MBTI 첫 화면으로 보내는 기존 오류 처리는 유지한다.
- [ ] 문의 작성 페이지의 인증 가드 도입 및 비로그인 복귀 동작 검토. 현재 페이지 진입 가드는 없고 작성 버튼과 등록 API에서 인증을 확인한다. 이번 단계에서는 인증 가드를 추가하지 않았다.

  - Playwright MCP의 새 비로그인 세션에서 마케팅 동의 화면 → `/login?returnTo=...` 이동과 목적지 보존 확인.
- 1단계 코드 검토 반영: `loginRedirect.ts`의 `getReturnToFromSearchParams`로 쿼리 추출·검증·홈 기본값 처리 이동. `LOGIN_RETURN_TO_PARAM` 상수를 로그인 URL 생성과 추출에 공통 적용.
  - 유틸 추출 후 관련 테스트 3개 스위트, 61개 테스트 및 타입 검사·변경 파일 ESLint 통과.

- 변경한 제품 파일 ESLint: 오류 없음. 기존 MBTI img 및 주류 상세의 미사용 인자 경고 3개 유지.
- Playwright MCP / 390×844 / 인증 목킹 없음:
  - 새 브라우저 세션에서 설정 CTA → 로그인 → 상단 뒤로가기 → 설정 query 보존 → 브라우저 뒤로가기 시 앞서 방문한 MBTI 화면으로 이동 확인.
  - 새 브라우저 세션에서 탐색 마이 버튼의 로그인 모달 → 로그인 → 상단 뒤로가기 → 탐색 query 보존 및 모달 닫힘 → 브라우저 뒤로가기 시 앞서 방문한 MBTI 화면으로 이동 확인.
